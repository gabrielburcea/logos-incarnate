# Architecture: Knowledge Graph

## Summary

The knowledge graph is the structural backbone for making biblical meaning visible.

It should connect words, people, places, themes, passages, events, genealogies, tribes, and nations in a unified model.

## Purpose

The graph should support:
- meaning exploration
- genealogy navigation
- relationship discovery
- context building
- selective visual graph display

## Core Principles

- graph should be meaning-oriented, not merely data-oriented
- graph should be queryable by words, people, places, passages, and themes
- graph should remain explainable and traceable
- graph should support both AI workflows and direct user interaction

## Core Node Types

- TranslationVerse
- Passage
- WordOccurrence
- Lemma
- Person
- Place
- Theme
- Event
- Nation
- Tribe
- GenealogyEntity

## Core Edge Types

- appears_in
- linked_to
- associated_with
- parent_of
- child_of
- member_of
- belongs_to
- occurs_with
- speaks_about
- takes_place_in
- connected_to_theme
- interpreted_by

## Example Queries

- show all key passages connected to a selected word
- show where a person appears and who they are related to
- show themes connected to a place
- show genealogy lines connected to a passage
- show related occurrences that influence contextual meaning

## AI Support Role

The graph should provide structured evidence to the AI meaning engine.

The AI should use graph-derived context to build concise explanations, occurrence summaries, and interpretive dossiers.

## UI Support Role

The graph should support:
- inline graph previews
- full graph explorer views
- entity cards
- filtered navigation
- relationship inspection
